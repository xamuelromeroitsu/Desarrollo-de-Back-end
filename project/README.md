# Proyecto transversal

## Propósito

Integrar los aprendizajes semanales en una API backend mantenible, con rutas, validación, persistencia, pruebas y documentación de arquitectura.

## Estructura

- `src/`: aplicación y módulos de dominio.
- `tests/`: pruebas automatizadas.
- `docs/architecture/`: decisiones, diagrama y límites del sistema.

## Plan de entregas

1. Definir el dominio y los casos de uso.
2. Separar rutas, controladores y servicios.
3. Añadir validación y manejo uniforme de errores.
4. Incorporar persistencia.
5. Crear pruebas y documentar evidencias.

## Criterios de calidad

El proyecto debe cumplir la rúbrica del [README principal](../README.md): funcionamiento 35%, explicación conceptual 25%, pruebas y diagnóstico 20%, organización e historial 10% y puntualidad 10%.
